# Governance

This repository supports the public Amadeus Open Source Community and OSPO site. It is a content and publication project rather than a standalone product runtime.

## Initial ownership

- **Initial code owner:** `@wherka-ama`
- **OSPO/community editorial owner:** to be confirmed before public launch
- **Project-story owners:** the relevant project maintainers
- **Legal/IP/security reviewers:** to be assigned according to the content

The `CODEOWNERS` file records the initial required reviewer. Additional owners should be added through a reviewed pull request once confirmed.

## Decision areas

- **Editorial scope:** OSPO/community owner, with project-owner input.
- **Technical changes:** code owner and required pull-request checks.
- **Project facts and metrics:** source owner plus OSPO/editorial review.
- **IP, legal, security or confidential material:** relevant specialist approval before publication.
- **Community conduct:** community leaders under `CODE_OF_CONDUCT.md`.

## Change process

Changes should be proposed through pull requests. Public claims should include a source, an `as of` date and any limitations. Content from `.tmp/` and `.memories/` is research material and is not public content.

The initial branch policy should require pull-request review and passing validation before merging to `main`. Direct pushes should be reserved for repository administration and emergency recovery.

## Publication status

The project is a working draft until the target repository, license, owners, publication boundary and GitHub Pages configuration are confirmed. A public launch should be announced through the site and recorded in the changelog.

## Succession

The organization-level OSPO/community ownership should maintain at least one backup code owner and one backup editorial owner. Ownership changes should be recorded in a pull request and reflected in `CODEOWNERS`, `MAINTAINERS.md` and this document.
